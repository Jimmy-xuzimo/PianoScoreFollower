# 架构与数据流

## 分层

`ui` 负责 Compose 界面；`score` 负责文件与曲库；`viewer` 是 alphaTab 的宿主；`audio`、`midi` 提供输入；`follower` 维护音乐位置；`performance` 定义两种输入共用的观测与位置接口。

```text
MusicXML / MIDI ─→ 私有曲库 ─→ alphaTab 乐谱与播放时间映射
                                      ↓
                              ScoreTimeline / ScoreGraph
                                      ↓
AudioRecord → AudioAnalyzer ─→ OnlineAligner ←─ MIDI 字节流 / 琴键与踏板
                                      ↓
                                FollowPosition
                                      ↓
                  置信度与浏览状态控制 → 光标 / 逐行跟随 / 分页
```

## 乐谱时间

使用每四分音符 960 tick。`tick` 是包含反复的播放时间；`notationTick` 和 `measure` 是谱面位置；`occurrence` 表示同一小节的第几次演奏。

网页侧 `graph.js` 由 Android 与离线评估工具共同使用。它调用 alphaTab 的 `MidiFileGenerator`、`MidiTickLookup`、`getRelativeBeatPlaybackRange` 获取时间；合并双手同刻事件，同时保留声部、谱表、音轨、延音状态和休止信息。不会通过判断一个数字是否大于小节起点来猜测绝对时间。

起音事件保存完整 MIDI 音高，持续中的音符另行保存。延音线目的音不当成新的触键。音轨、谱表筛选重新生成目标结构。声部时值超出小节范围时给出错误，避免展示看似成功的错误跟谱。

## 输入与对齐

- `PerformanceInput` 是输入源接口；`PerformanceObservation` 使用单调时间，包含音高特征、起音、有效声音状态、输入精度和分析延迟。
- `ListeningEngine` 以独立线程采集和分析，使用有界队列；读取实际采样率及单调采样时间，队列超载或设备中断时暂停并反馈。每个采集会话拥有独立回调，旧会话迟到帧不会进入新乐谱。
- `AudioAnalyzer` 结合 2048 点起音分析、8192 / 16384 点钢琴谐波特征及噪声估计。保留八度；较长窗口用于低音，较短窗口用于快速高音。
- `OnlineAligner` 在少量局部序列候选上执行在线概率对齐，使用音高、持续音、攻击变化与节奏先验。连续音频证据可以弥补部分遗漏的起音。
- 独立的全曲序列候选为每条路径保留证据；明确静音后重建独立搜索。分数相同的远处候选表示无法区分的乐句或反复次数，保持定位状态，等待后续音符。
- 显示位置补偿分析延迟，并限制在下一个未确认触键之前。静音不会推进已确认位置。
- `FollowPosition` 包含事件索引、播放 tick、谱面小节、反复次数、速度、置信度及等待 / 跟随 / 失配 / 定位状态。

当前音频算法仍未达到全部验收指标；实现机制不等于真实设备准确率保证。详见测试报告。

## MIDI 与录制

`MidiInput` 使用 Android `MidiManager` 和设备输出端口接收数据。解析器保留跨消息边界的运行状态，忽略实时消息及不支持的系统消息，处理零力度 Note On、Note Off、通道和踏板。物理按键与踏板持续音分别维护；短触键在分组窗口中仍被保留。

多个端口允许选择并记忆设备标识；断开设备暂停依赖它的活动。麦克风模式不会被同时连接的 MIDI 输入驱动。

录制保存原始微秒时间与 MIDI 消息。每三秒写一次原子快照，正常停止保存最终版本；异常终止最多可能丢失最近一次快照后的事件。原始演奏回放使用原始 MIDI 时间；谱面转换是独立的量化派生结果。

`NotationOptions` 默认 120 BPM、4/4、C 大调、十六分音符网格。`MidiToMusicXml` 支持双谱表、重叠声部、跨小节延音、速度变化与多部分导入。它不承担完整乐谱编辑器的功能。

## 网页桥与导航

每条网页事件携带 `generation` 和 `layoutVersion`。宿主拒绝旧乐谱或旧排版事件。异步读取也使用请求代次，避免较早的请求覆盖较新的选择。

乐谱、播放器和跟谱分别就绪。音源按播放需要加载，故排版与听音无需等待音源解码。切换功能时停止不兼容的音频活动；后台停止活动，演奏页可保持屏幕常亮。

默认逐行跟随。分页使用实际谱行边界并保留边缘上下文；低置信度、失配、等待状态及手动浏览均禁止自动移动。手动恢复后重新锚定当前位置。旋转只重排谱面，保留音乐 tick。

## 存储与迁移

曲库每个项目各自保存原始文件、排版文件与元数据；元数据最后提交，采用原子写入。记录、外观和旧图片页序分别保留。演奏导航、自动定位和自动移动偏好也持久化。存储错误进入界面状态，不默默吞掉。

旧版 `score/current.bin` 与 `current.meta` 只读迁入新曲库，迁移成功后写标记，旧文件不自动删除。旧版只存转换后 XML 的 MIDI 文件无法还原原始 MIDI，不会伪造“原始文件”。原图片目录和索引沿用，首次读取保留 `index.legacy-v1.bak`，索引写入改为原子提交。

## 调试入口

只有 `src/debug` 包含测试广播接收器，受系统 `DUMP` 权限保护，供 ADB 注入测试 MIDI 或音频。Release 清单不含此接收器，且关闭 WebView 调试。注入源验证处理管线，不能证明实体 USB、电钢琴驱动或手机麦克风声学效果。

## 官方 Material 3 界面

主界面直接使用 `androidx.compose.material3` 的 Scaffold、NavigationBar / NavigationBarItem、TopAppBar、Button / IconButton、Card / ListItem、Switch、Slider、OutlinedTextField、AlertDialog 和 Snackbar。主题统一通过 MaterialTheme 和官方动态取色接口提供。琴谱、音高读数和琴键状态为专用内容展示；应用操作控件使用官方实现。


## 简谱与评分

`numbered.js` 使用与跟谱相同的导出图，按首次谱面访问生成可重排的声部 / 和弦 / 休止，反复只印一次。布局从实际 DOM 行边界重新生成系统和分页；点击与光标通过每次播放访问的 tick 映射回同一谱面。五线谱渲染器在真实宽度下保留，切换视图不依赖音源解码。

`AssessmentEngine` 接收与跟谱相同的 `PerformanceObservation` 和已确认 `FollowPosition`。MIDI 的新触键独立于踏板保持的 sounding，防止持续音重复评分。待定触键在后续上下文确认时与应弹位置匹配，错音消耗一个应弹位置，其余为漏音，多余为额外触键。音乐时钟结合曲谱速度、练习速度和显式暂停；实时状态限每秒四次发布，避免音频线程持续分配整份评分结果。音频的低置信度窗口保留为 UNCERTAIN，不强行输出确定分数。

演奏页是全屏 WebView 加 Material 3 悬浮控制条。设置通过 Material 3 ModalBottomSheet 展开，不改变 WebView 尺寸；隐藏控制条同样不触发谱面重排。AppRoot 在演奏路由移除导航栏并清空系统 inset，演奏页负责临时隐藏系统栏和返回时恢复。


## 位置惯性与跳转确认

`PositionContinuity` 在 `OnlineAligner` 提交离散位置前做滞回确认。向后、跨四个以上事件或超过当前节奏可解释距离的前跳，需要至少三个连续向前推进的候选（至少 180ms），单个重复音或来回摇摆的候选不累计。刚确认跳转的 1.5 秒内反向再跳，需要五个推进候选。低相似度与回到正常局部路径会清空候选。

确认前保留音乐位置，状态为 LOCATING，自动移动暂停；保留的候选搜索仍在继续，不把错误输入丢弃成静音。两拍以内的局部校正保留，以免慢速长音的时刻修正被强行顶在前面。显示层 `navigation.js` 单独稳定跨行锚点：小幅回移跨行持续 650ms 后才移动视口，同一行内正常校准。大幅确认重弹及用户点按立即生效。按谱面反复路径继续前进时，播放 tick 向前，谱面小节可向后，因此不会把正常反复误当成回跳抑制。

这是有延迟的证据门槛，需要同时报告位置准确率、恢复延迟和回跳次数，不能仅凭少跳动声称跟谱更准确。


位置先验根据最后确认位置、速度和已过去时间，对不连续候选施加有界的对数距离代价；持续失配后先验随时间衰减，明显停顿后暂时释放。该先验只参与候选选择，不靠时间独自推进位置。跨超过 16 拍的连续演奏跳转需六个推进候选，明显停顿后重新起弹采用三音门槛；全曲搜索已积累的同一时刻、同一候选证据可复用，避免重复等待。序列证据允许较长音符间隔，单个持续音仍不增加计数。局部连续匹配可靠时优先保留本地路径，失配时也不从 beam 中完全驱逐原位置附近的候选。

一次网页桥调用按顺序更新导航允许状态、稳定锚点、实际光标和分页。行跟随与分页都基于确认锚点，正常节奏插值不会独自触发提前翻页。网页重排、点按和停止会重置导航确认历史。
